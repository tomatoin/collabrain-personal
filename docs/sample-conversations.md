# 테스트용 샘플 대화

앱의 모든 기능을 훑어보기 위한 가상 데이터. **2주치**로 되어 있어야 점수 추이(▲▼)를 볼 수 있으므로, 1주차를 먼저 분석해 기준선을 만든 뒤 2주차를 분석한다.

## 설정값

| 항목 | 값 |
|---|---|
| 내 이름 / 닉네임 | `김현주` |
| 내 직무 | `기획` |

## 테스트 순서

1. **1주차** 채널 + 스레드 2개를 각각 블록으로 붙여넣고 분석
   - 자기인식 입력란: `기획서 정리하는 데 대부분 썼어요`
2. 홈 화면 확인 → **스마트 워커** 또는 **히어로** 계열, 기획 비중 높음
3. **2주차** 채널 + 스레드 2개를 붙여넣고 분석
   - 자기인식 입력란: `이번에도 기획 위주로 했어요`
4. 홈 화면 확인 → **하드 워커** 계열, PM 비중 급증, 응답 적시성 ▼, 직무 괴리 배너 노출
5. 동료 / 기록 탭 확인

## 각 기능이 어디서 걸리는지

| 기능 | 어디서 검증되나 |
|---|---|
| 응답 적시성 (타임스탬프) | 1주차는 수 분 내 응답 / 2주차는 수 시간 지연 |
| `hasTimestamps: false` 경로 | 아래 **타임스탬프 없는 버전**으로 별도 테스트 |
| 업무 도메인 4분류 | 1주차 기획 중심 → 2주차 PM 중심으로 이동 |
| 직무 괴리 배너 | 2주차에서 직무(기획) ≠ 최다 도메인(PM) |
| 자기인식 갭 | 2주차 자기인식("기획 위주")과 데이터(PM 최다)가 어긋남 |
| `self_promise` + 마감 + 대상자 | 2주차 채널의 "수요일까지 정산 자료 보내드릴게요" |
| `system_experiment` | 가장 낮은/가장 크게 하락한 축에서 자동 생성 |
| 동료 사용설명서 | 박서준·이하늘·정민우·강수아 4명, 각자 다른 패턴 |
| 친절도 | 1주차 이모지·완충 표현 / 2주차 건조해짐 |
| 부하(load) | 2주차 메시지 수·수신량 급증 |

`hasTimestamps: false` 경로와 응답 적시성 각주(`*`)를 확인하기 위한 별도 샘플. 위 데이터와 섞지 말고 전체 기록을 지운 뒤 이것만 단독으로 분석한다.

```
정민우: 김현주님 이번 스프린트 기획 범위 확정 가능할까요?
김현주: 네 오늘 중으로 확정해서 올릴게요
김현주: 검색 필터 스펙 초안 정리했습니다. 카테고리 다중선택, 가격 구간 슬라이더, 정렬 4종입니다. 정렬은 이번 스프린트에서 빼는 게 나을 것 같은데 의견 주세요
박서준: 정렬은 인덱스 새로 타야 해서 다음 스프린트가 나을 것 같습니다
김현주: 넵 백로그로 옮기겠습니다
이하늘: 필터 UI 시안 두 가지 방향으로 잡아봤습니다
김현주: 두 번째가 더 맞을 것 같습니다. 슬라이더가 계속 보이는 쪽이요
강수아: 가격 슬라이더 최소 단위는 어떻게 할까요?
김현주: 5000원 단위로 하고 직접 입력도 가능하게 하면 좋겠습니다
정민우: QA 시나리오 일정은요?
김현주: 목요일까지 초안 드리겠습니다
```

# 동료별 의도된 패턴

분석 결과의 **동료** 탭에서 아래와 비슷한 서술이 나오면 정상이다.

| 동료 | 심어둔 특징 |
|---|---|
| 박서준 | 짧고 즉각적인 응답. 기술적 제약을 근거로 판단을 도움 |
| 이하늘 | 배경/의도를 설명해주면 방향을 빠르게 수정. 시안 기반 커뮤니케이션 |
| 정민우 | 일정과 담당자를 먼저 묻는 관리자형. 요청이 짧고 반복적 |
| 강수아 | 응답이 느리지만 상세함. 구현 리스크와 예외 케이스를 먼저 제기 |
