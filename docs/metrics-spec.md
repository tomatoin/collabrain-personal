# 5축 지표 채점 기준 (확정)

출처: B2B 프론트엔드 번들(`index-DfDAoNka.js`)에 실제로 박혀 있는 산식 + 개인용 프로토타입(`collabrain-personal.html`) 프롬프트.

## 1. 지표별 산식

| 키 | 표시명 | 정의 | B2B 실제 산식 | 붙여넣기 텍스트로 계산 가능? |
|---|---|---|---|---|
| `digitalization` | 디지털화지수 | 디지털 협업도구(Slack·Jira 등) 활용 커뮤니케이션 지수 | 메시지수 40% + 메시지량 40% + 스레드 내 대화률 20% | 가능 |
| `responsiveness` | 응답 적시성 | 업무 요청·피드백에 대한 응답 여부 및 속도 | 평균 응답시간 50% + 응답률(단독 멘션) 30% + 응답률(멀티 멘션) 20% | **타임스탬프 필요** |
| `clarity` | 의사전달 명확성 | 업무 요청에 핵심내용 포함 여부 및 양식 적합성 | 핵심정보 포함률 50% + 작성 양식 적합성 50% | 가능 |
| `initiative` | 적극성 | 이슈·문제사항에 대한 의견 발언 및 책임감 | 의견 발언률 50% + 의견 주도성 50% | 가능 |
| `kindness` | 친절도 | 작성한 메시지 톤 유형(공격적/사무적/비꼬임 등) | 메시지톤 80% + 이모지 포함률 20% | 가능 |

> **`listening`(경청·이해)은 제외한다.** B2B 5축에 존재하지 않아 검증된 산식이 없고, 이 축만 근거 없이 채점되면 해당 축의 추이(▲▼) 신뢰도가 떨어진다. 기획서·프로토타입의 6축 표기는 5축으로 수정한다.

## 2. 부하(Load) 축 — 업무 유형 판정용

B2B 노드 상세의 업무 부하 구성:

- **직접 업무** = 본인이 발신한 메시지
- **읽기 업무** = 본인이 수신한 메시지
- **총 부하** = 직접 업무 + 읽기 업무
- **과부하도** = 총 부하가 기준선을 넘는 정도

## 3. 업무 유형 (히어로 맵 4분면)

부하(가로축) × 종합점수(세로축)

| 유형 | 영문 키 | 조건 |
|---|---|---|
| 스마트 워커 | `smart` | 부하 낮음 · 점수 높음 |
| 히어로 | `hero` | 부하 높음 · 점수 높음 |
| 하드 워커 | `silo` | 부하 높음 · 점수 보통 |
| 협업 단절 | `disconnect` | 부하 낮음 · 상호작용 적음 |

## 4. 업무 도메인 분류 (관점 B)

`개발 / 기획 / 디자인 / PM` 4분류.

B2B에서 "직무"는 멤버에게 배정된 속성이지만, 개인용에서는 **본인 메시지 내용을 이 4개 도메인으로 분류**해 비율을 낸다. 이게 P1("직함과 실제 업무의 괴리")을 직접 잡아내는 지표가 된다 — 직무는 기획인데 메시지의 45%가 PM 업무인 상태를 보여주는 것.

> 기획서 2.2는 `Creating / Coordinating / Resolving` 3분류를 제안했으나, 도메인 4분류로 대체한다.

## 5. 채점 일관성 원칙 (중요)

각 축을 하위 구성요소 + 가중치로 쪼개서 프롬프트에 명시한다. "0~100점 매겨줘"로 끝내면 매 분석마다 잣대가 달라져 추이(▲▼) 비교가 무의미해진다.

- 붙여넣기 안내에 **타임스탬프 포함**을 명시한다 (`[10:32] 나: ...` 형식). 없으면 `responsiveness`의 응답시간 항목(50%)을 계산할 수 없다.
- 타임스탬프가 없는 경우 `responsiveness`는 응답률만으로 채점하고, 그 사실을 UI에 표기한다.
