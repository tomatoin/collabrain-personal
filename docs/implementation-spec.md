# 콜라브레인 퍼스널 — 구현 스펙 (서버 없음, 2-3시간 프로토타입용)

> 이 문서는 클로드 코드에 그대로 전달해서 바로 코딩을 시작할 수 있는 수준의 스펙이다. 제품 배경·전체 비전은 별도 문서("콜라브레인 퍼스널 제품 기획서 최종본")를 참고하되, 클로드 코드에는 **이 문서만** 넘겨도 충분하도록 필요한 맥락을 요약해 포함했다.

---

## 1. 무엇을 만드는가 (한 줄)

Slack에서 복사한 대화를 붙여넣으면, 브라우저 안에서 바로 AI가 분석해서 "이번 주 나의 상태"(업무 유형 + 6축 점수 + 패턴 서술 + 이번 주 할 일 1개)를 보여주고, 그 기록이 브라우저에 계속 쌓여 다음번엔 지난 기록과 비교되는 개인용 웹앱.

---

## 2. 이번 빌드에 포함하는 것 / 빼는 것

### 포함 (2-3시간 목표 범위)
- 붙여넣기 입력 (채널 대화 블록 + 스레드 블록, 여러 개 추가 가능)
- 클라이언트에서 직접 Anthropic API 호출 (사용자 본인 API 키, 로컬 저장)
- 홈 화면: 업무 유형(orb) + 6축 점수(추이 포함) + 이번 주 서술 + 이번 주 할 일(Commitment) 카드
- **Commitment 엔진**: "이번 주 할 일" 하나가 시스템 제안이든(실험) 본인이 대화 중에 한 약속이든(⑧ 셀프 약속) 같은 데이터 구조로 저장·표시. 이번 빌드에서는 **UI상 하나의 카드로 통합** (구분 뱃지만 다르게: "제안" vs "내 약속")
- **동료 사용설명서(⑥)**: 파싱 과정에서 어차피 상대방 발화를 실명으로 구분하므로, 그 정보를 그대로 모아 "이 사람과 나눈 대화 요약" 카드로 보여주는 화면 하나 추가 (실명 사용, 상세는 4.3)
- 기록 히스토리 (지난 분석들 리스트, 브라우저 저장)
- 전체 기록 삭제 버튼

### 빼는 것 (서버 필요 또는 시간 초과라서 이번엔 제외 — 무엇인지·어떻게 만들지는 9장에 설계만 남김, 코드는 없음)
- 서버, DB, Slack OAuth 자동 연동
- 진짜 푸시 알림 (인앱 배너만 유지)
- 동료 익명 벤치마크 비교 (모수 없음)
- ⑤ 자동 회고·커리어 로그 → 9.1
- ⑨ 감사·인정 수지 코치 → 9.2
- ④ 번아웃 조기감지 → 9.3
- ⑦ 관계 온도 레이더 → 9.4
- ⑩ 재개 브리핑 → 9.5

## 3. 기술 스택

- **프레임워크 없이 순수 HTML/CSS/JS 단일 파일 1개.** 빌드 도구·번들러 불필요, 파일 열면 바로 실행. 클로드 코드가 프레임워크(React 등)로 짜고 싶어하면 Vite+React도 무방하나, 2-3시간 목표엔 순수 HTML 쪽이 안전
- **저장소**: `localStorage` (브라우저 내장, 별도 설치 불필요)
- **API 키**: 설정 화면에서 사용자가 Anthropic API 키 입력 → `localStorage`에 저장 → 클라이언트에서 직접 `https://api.anthropic.com/v1/messages` 호출
  - 주의: 실제 배포 시 CORS 이슈 발생 가능. Anthropic API가 브라우저 직접 호출을 막는 경우, 최소한의 프록시(Vercel의 서버리스 함수 1개, "서버"라기보다 API 키 은닉용 중계 함수)가 필요할 수 있음 — 이건 코딩 중 확인 필요 항목으로 남김 (8장 참고)

## 4. 데이터 스키마 (localStorage)

```js
// key: "collabrain_entries" → JSON.stringify(Entry[])
Entry = {
  id: string,
  date: string, // ISO
  type: "스마트 워커" | "히어로" | "하드 워커" | "협업 단절",
  typeReason: string,
  scores: {
    digitalization: number, responsiveness: number, clarity: number,
    initiative: number, kindness: number, listening: number
  },
  narrative: string,
  whyThisMatters: string,
  commitments: Commitment[],       // 이번 주 카드에 표시할 항목들 (보통 1~2개)
  colleagueMentions: string[]      // 이 entry에서 언급된 동료 실명 목록 (아래 4.3 프로필 갱신용)
}

Commitment = {
  id: string,
  source: "system_experiment" | "self_promise",
  title: string,
  description: string,
  status: "proposed" | "accepted" | "observing" | "done" | "missed",
  deadline: string | null,   // self_promise만 해당
  createdAt: string
}

// key: "collabrain_colleagues" → JSON.stringify(ColleagueProfile[])
ColleagueProfile = {
  name: string,              // 실명 (4.3 참고)
  interactionCount: number,
  lastInteraction: string,   // ISO
  observedPatterns: string[] // "요청에 빠르게 응답함", "짧은 형식을 선호함" 등 LLM이 생성한 관찰 서술
}

// key: "collabrain_settings" → { apiKey: string, selfName: string }
```

## 5. 화면 목록

|---|---|
| **설정** (최초 1회) | API 키 입력, 본인 이름/닉네임 입력(붙여넣은 대화에서 "나"를 구분하는 기준) |
| **홈** | 최신 Entry: 업무유형 orb, 6축 점수(지난 기록 대비 ▲▼), 서술 카드, Commitment 카드(들), "새로 분석하기" 버튼 |

| **기록** | 과거 Entry 리스트 (날짜순) |

## 6. 분석 API 호출 — 프롬프트 템플�트

기존 채점 파이프라인(6대 지표) + 업무유형(히어로맵) + Commitment 후보 + 동료 관찰을 **한 번의 API 호출**로 처리한다 (호출 횟수를 줄여 속도·비용 확보).

```
system:
당신은 개인의 Slack 협업 데이터를 분석해 "나의 상태"를 알려주는 도구입니다.
입력된 대화에서 화자를 구분하세요: "{selfName}"으로 표시된 발화가 본인입니다. 나머지는 실명 그대로 유지하세요(익명화하지 않음 — 이 앱은 본인만 보는 개인용 기록입니다).

아래 6개 지표를 0~100 점수로 채점(본인 발화 기준):
- digitalization, responsiveness, clarity, initiative, kindness, listening
  (각 정의는 기존 콜라브레인 6대 지표와 동일 — 메시지량/응답성/명확성/적극성/친절도/경청이해)

업무 유형 1개 판정: "스마트 워커"(부하 낮음·점수 높음) / "히어로"(부하 높음·점수 높음) / "하드 워커"(부하 높음·점수 보통) / "협업 단절"(부하 낮음·상호작용 적음)

이번 주 Commitment 후보를 최대 2개 만드세요:
- system_experiment 타입: 데이터로 관측 가능한 행동 제안 1개 (예: "위임 1건 시도")
- self_promise 타입: 본인이 대화 중 실제로 한 약속이 있다면 추출 (예: "수요일까지 보내드릴게요") — 없으면 생략

대화에 등장한 동료별로 관찰 서술 1~2개씩 생성 (점수 아님, 서술만. 예: "요청에 빠르게 응답함", "짧고 명확한 형식을 선호하는 것으로 보임")

절대 원칙: 사람을 진단하거나 서열화하지 말고 관찰된 패턴만 서술. JSON만 출력, 다른 텍스트 금지.

{
  "type": "...", "typeReason": "...",
  "scores": {...},
  "narrative": "...", "whyThisMatters": "...",
  "commitments": [{"source":"...", "title":"...", "description":"...", "deadline": null}],
  "colleagues": [{"name":"...", "patterns": ["...", "..."]}]
}

user:
[붙여넣은 채널 블록 + 스레드 블록들을 구분해서 전달]
```

## 7. 구현 순서 (클로드 코드용, 2-3시간 배분 가이드)

1. (20분) 단일 HTML 파일 스캐폴드 + 설정 화면(API 키, 이름 입력) + localStorage read/write 유틸
2. (30분) 붙여넣기 화면 (채널/스레드 블록 동적 추가 UI)
3. (30분) API 호출 함수 + 6장 프롬프트 적용 + 에러 핸들링
4. (40분) 홈 화면 렌더링 (유형 orb, 점수바+델타, 서술 카드, Commitment 카드)
5. (30분) 동료 화면 + 기록 화면
6. (20분) 스타일링 다듬기, 반응형 확인, 전체 삭제 버튼

## 8. 확인 필요 (클로드 코드가 코딩 중 판단)
- 브라우저에서 `api.anthropic.com`으로 직접 fetch가 CORS 없이 되는지 실제 확인 필요. 막히면 최소한의 서버리스 프록시 함수 1개 추가 검토 (이건 "서버"라기보다 API 키를 헤더에 실어 중계만 하는 함수라 이번 무서버 원칙과 크게 배치되지 않음)
- Commitment 카드에서 "제안" vs "내 약속" 뱃지 UI 톤 (색상 등)은 클로드 코드 재량

## 9. 향후 기능 설계 (이번 빌드엔 구현 안 함 — 무엇인지·어떻게 만들지만 남김)

이번 2-3시간 빌드에서 코드로 만들지 않지만, 클로드 코드가 지금 짜는 구조가 나중에 이 기능들을 받아들일 수 있는 형태인지 참고하도록 남겨둔다. **지금 이 항목들을 구현하지 말 것** — 화면·로직 없이 이 문서에서 이해만 하고 넘어가면 된다.

### 9.1 ⑤ 자동 회고·커리어 로그
- **뭔지**: 완료 선언·감사 수신 같은 성과 신호를 Entry에서 주간 자동 추출해 쌓아두고, 나중에 "자기평가서 초안" 같은 형태로 뽑아주는 본인 전용 아카이브. 회사 제출용 아님
- **필요한 데이터**: `CareerLogItem = { date, description, competencyTag, sourceEntryId }` — Entry 분석 시 LLM 응답에 `achievements: []` 필드를 추가하면 자연스럽게 쌓임 (지금 6장 프롬프트엔 없음, 나중에 추가)
- **화면 아이디어**: "기록" 화면에 탭 하나 추가해서 성과만 모아보기 + "텍스트로 내보내기" 버튼

### 9.2 ⑨ 감사·인정 수지 코치
- **뭔지**: 리더/팀 리드 역할인 사용자 대상. 받은 도움 대비 표현한 인정의 비율을 추적, 위임 비율도 함께 봄
- **필요한 데이터**: `RecognitionBalance = { colleagueName, helpReceivedCount, recognitionExpressedCount }`, 그리고 설정 화면에 "다른 사람을 이끄는 역할인가요?" 온보딩 질문 하나 추가해서 이 기능 노출 여부를 분기
- **화면 아이디어**: 홈 화면에 조건부 카드 하나("리더용" 응답한 사용자에게만) — 막대로 수지 비율, 인정 제안 문구

### 9.3 ④ 에너지 변화 감지 (구 "번아웃 감지" — UI엔 이 단어 안 씀)
- **뭔지**: 평소(직접 저장된 과거 Entry들) 대비 최근 패턴이 달라졌는지 감지 — 심야 활동 비율, 짧은 답장 비율 등
- **필요한 데이터**: 이미 저장 중인 `Entry` 리스트만으로 계산 가능 — 서버 없이도 됨. 단, **Entry가 최소 4~6개(주) 이상 쌓여야** 의미 있는 비교가 됨
- **구현 아이디어**: 새 Entry 저장 시, 과거 Entry들의 평균(baseline)과 이번 주를 비교하는 함수 하나 추가 → 차이가 크면 홈 화면에 중립적 문구 배너("최근 평소와 다른 리듬이 이어지고 있어요") — 이 계산 로직은 나중에 추가해도 기존 데이터 손실 없이 바로 작동함 (과거 기록이 이미 쌓여있을 것이므로)

### 9.4 ⑦ 관계 온도 레이더
- **뭔지**: 특정 동료와의 상호작용이 평소보다 줄었는지(냉각) 감지
- **필요한 데이터**: 지금 `ColleagueProfile`은 최신 상태만 덮어쓰는데, 이 기능을 위해서는 **주차별 스냅샷**이 필요함 — `ColleagueProfile.history = [{week, interactionCount}]` 형태로 확장
- **비고**: 지금 스키마(4장)를 이대로 둬도 나중에 `history` 필드만 추가하면 되므로 지금 구조를 바꿀 필요는 없음. 다만 스냅샷이 없으면 과거로 소급 계산은 안 되고, **이 필드를 추가한 시점부터** 쌓이기 시작함 — 그래서 미리 필드 이름만 예약해두는 것도 방법

### 9.5 ⑩ 재개 브리핑
- **뭔지**: 3주+ 연락이 없던 동료가 다시 등장하면, 마지막 맥락(미결 약속·마지막 대화 요지)을 브리핑
- **필요한 데이터**: `ColleagueProfile.lastInteraction`(이미 있음) + 그 동료와 연결된 미해결 `Commitment`(8.4 Commitment의 관련 인물 필드 필요 — 지금 스키마엔 없음, `Commitment.relatedColleague` 필드 추가 필요)
- **화면 아이디어**: 새 Entry 분석 시 대화에 등장한 동료 중 `lastInteraction`이 21일 이상 지난 사람이 있으면 홈 화면에 브리핑 카드 자동 표시

**공통 원칙**: 위 5개는 전부 "이미 저장되고 있는 Entry/ColleagueProfile 데이터를 다르게 계산·조합"하는 것들이라, **서버 없이도 나중에 추가 가능**하다. 지금 만드는 핵심 루프(붙여넣기→분석→저장)만 튼튼하면, 이 기능들은 로컬 계산 로직만 얹으면 되는 구조다.

### 9.6 온보딩 방식 전환 (Slack 연동 이후)
- **지금**: 붙여넣은 텍스트만큼만 분석 (과거 데이터를 한 번에 몰아서 보여주는 방식)
- **Slack API 연동 이후 (서버 도입 시점)**: 데이터가 수동 개입 없이 자연스럽게 쌓이므로, 첫 화면부터 다 보여주기보다 **"Week1: 알아가는 중 → Week2 → Week4+: 패턴 확정"처럼 신뢰를 점진적으로 쌓아가는 온보딩으로 전환 검토.** 지금 붙여넣기 방식에 이 흐름을 억지로 적용하면 "가입 첫 주에 볼 게 없어 이탈"하는 문제가 생기지만, 실시간 연동에서는 자연스러운 흐름이 될 수 있음
- 이번 빌드에서는 해당 없음 — Slack OAuth 연동 시점에 재검토
